# Установка knitERP на облачный сервер Beget

Решение D08: рабочий сервер — VPS Beget в России. На сервере работают SQL Server 2022 Express и приложение в Docker,
HTTPS даёт Caddy (сертификат Let's Encrypt выпускается и продлевается сам). Файлы — в `deploy/beget/`.

## 1. Что заказать

| Что | Значение |
|---|---|
| Услуга | VPS (облачный сервер), **не** виртуальный хостинг — на хостинге .NET и SQL Server не работают |
| Система | Ubuntu 24.04 |
| Ресурсы для пилота | 2 ядра, **4 ГБ памяти** (SQL Server требует не меньше 2 ГБ), диск 40 ГБ NVMe |
| Доступ | вход по SSH-ключу; пароль root после настройки отключить |
| Домен | поддомен, например `erp.ваша-фабрика.ru`, DNS-запись **A** — на IP сервера |

Ограничения SQL Server Express: база до 10 ГБ, один процессор и до ~1,4 ГБ памяти под кеш. Для склада одной фабрики
этого хватит на годы; при росте переходят на Standard без изменения программы.

Персональные данные сотрудников хранятся на сервере в России. Уведомить Роскомнадзор об обработке персональных данных — обязанность
организации как оператора, это делается вне программы.

## 2. Установка (около 20 минут)

Подключиться к серверу по SSH и выполнить:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/basilsolanji-hash/kniterp.ru.git /opt/kniterp/src
cd /opt/kniterp/src && git checkout claude/fervent-volta-3pn88r
cd kniterp/deploy/beget
./install.sh erp.ваша-фабрика.ru
```

Скрипт:
1. ставит Docker, Caddy, openssl из репозиториев Ubuntu;
2. создаёт `.env` со случайными паролями базы и **мастер-ключом**, ключ шифрования копий `/opt/kniterp/backup.key`;
3. собирает образ приложения и запускает SQL Server Express (порт базы наружу не открыт);
4. применяет миграции и создаёт учётную запись базы `kniterp_app` только для чтения и записи данных
   (без права менять схему и отключать триггеры журнала);
5. запускает приложение, настраивает HTTPS и брандмауэр (открыты только 22, 80, 443);
6. ставит резервное копирование по расписанию и делает первую копию.

**Сразу после установки** перепишите в сейф Владельца (на бумагу или отдельный носитель, не в почту):
- `MASTER_KEY` из файла `.env` (`cat .env`);
- содержимое `/opt/kniterp/backup.key`.

Без мастер-ключа не расшифровать вход с кодом и не проверить журналы, без ключа копий — не восстановить базу.

Проверка: `https://erp.ваша-фабрика.ru/health` отвечает `Healthy`.

Если на шаге сборки сервер не может скачать образы с `mcr.microsoft.com` или пакеты с `nuget.org` — проверьте
`docker pull mcr.microsoft.com/mssql/server:2022-latest`; при блокировке напишите разработчику: образ можно собрать
заранее и передать файлом.

## 3. Организация и Владелец

```bash
cd /opt/kniterp/src/kniterp/deploy/beget
docker compose run --rm app create-organization \
  --name "Общество с ограниченной ответственностью «…»" --short-name "ООО «…»" \
  --inn <ИНН> --kpp 770501001 --kpp-verified=yes \
  --owner-email <почта Владельца> --owner-name "<ФИО>" \
  --url https://erp.ваша-фабрика.ru
```

Ссылку из ответа передать Владельцу лично. Владелец задаёт пароль, подключает приложение-аутентификатор и **сразу
выпускает резервные коды** (программа предложит сама). Затем — второй Администратор и по `docs/pilot.md`.

## 4. Резервные копии

| Что | Когда | Где |
|---|---|---|
| Полная копия | каждую ночь в 02:30 UTC | `/opt/kniterp/backups/enc/` |
| Журнал транзакций | каждые 15 минут | там же |
| Хранение | 35 дней | |

Копии сразу шифруются (AES-256, ключ `/opt/kniterp/backup.key`), незашифрованный файл удаляется.
Журнал: `/var/log/kniterp-backup.log`.

**Копия вне сервера обязательна**: если сервер пропадёт, локальные копии пропадут с ним. Подключите S3-совместимое
хранилище (например, S3-хранилище Beget или другого провайдера): `apt-get install rclone`, `rclone config` (имя, например
`s3`), затем в `.env` строка `RCLONE_REMOTE=s3:kniterp-backups` — каждая новая копия будет выгружаться туда.

Проверка восстановления раз в месяц (D54) — в отдельную базу, рабочая не трогается:

```bash
cd /opt/kniterp/src/kniterp/deploy/beget
./restore.sh /opt/kniterp/backups/enc/kniterp-full-<дата>.bak.gz.enc /opt/kniterp/backups/enc/kniterp-log-<после неё>.trn.gz.enc …
```

Скрипт расшифрует копии, восстановит базу `kniterp_restore`, проверит её (`DBCC CHECKDB`) и покажет контрольные цифры.
Восстановление рабочей базы после аварии: `docker compose stop app`, затем `TARGET=kniterp ./restore.sh …`, затем
`docker compose up -d app`, затем «Проверка целостности» и «Сверка».

## 5. Новая версия

```bash
cd /opt/kniterp/src/kniterp/deploy/beget && ./update.sh
```

Скрипт берёт код, делает полную копию (точка отката), собирает образ, применяет миграции, запускает и ждёт `Healthy`.
Откат: `docker compose stop app`, восстановить копию из этого шага (`TARGET=kniterp ./restore.sh …`), вернуть прежнюю
версию кода (`git -C ../.. checkout <коммит>`), затем `docker compose build app && docker compose up -d app`.

## 6. Если войти не может никто из администраторов

Последний рубеж аварийного доступа (D06) — на сервере, вдвоём и с актом:

```bash
docker compose run --rm app emergency-access --email <почта> --reason "<причина, № акта>" --url https://erp.ваша-фабрика.ru
```

## 7. Наблюдение и оповещения

`install.sh` ставит `monitor.sh` в cron каждую минуту. Он проверяет:
- `/health` приложения (`Healthy` — база доступна и схема актуальна);
- свободное место на диске (меньше 10% — проблема);
- свежесть копий: полная — не старше 26 часов, журнал транзакций — не старше 60 минут;
- сертификат HTTPS — раз в час, проблема за 14 дней до окончания.

Оповещение приходит после двух неудачных проверок подряд, при восстановлении — сообщение «Восстановлено»,
нерешённая проблема напоминает о себе раз в 6 часов. Оповещения пишутся в журнал системы
(`journalctl -t kniterp-monitor`) и, если заданы в `.env`, уходят в Telegram и на почту.

**Telegram:**

1. В Telegram написать @BotFather → `/newbot` → получить токен бота.
2. Написать боту любое сообщение (или добавить его в общий чат), открыть
   `https://api.telegram.org/bot<токен>/getUpdates` и взять `chat.id`.
3. Вписать в `/opt/kniterp/src/kniterp/deploy/beget/.env` строки `TELEGRAM_BOT_TOKEN=…` и `TELEGRAM_CHAT_ID=…`.

**Почта** — через обычный почтовый ящик (отправлять письма прямо с облачного сервера нельзя: порт 25 закрыт, а такие
письма попадают в спам). Удобно завести отдельный ящик, например `kniterp-alerts@yandex.ru`:

1. Яндекс ID → «Безопасность» → «Пароли приложений» → «Почта» — создать пароль приложения (обычный пароль не подойдёт).
2. В `.env` вписать:
   ```
   ALERT_EMAIL_TO=владелец@фабрика.ru,админ@фабрика.ru
   SMTP_URL=smtps://smtp.yandex.ru:465
   SMTP_USER=kniterp-alerts@yandex.ru
   SMTP_PASSWORD=<пароль приложения>
   ```
   Для Mail.ru — `smtps://smtp.mail.ru:465` и пароль для внешних приложений.

Проверить каналы: `./monitor.sh test` — пробное сообщение в Telegram и на почту.

Тот же ящик отправляет письма «Забыли пароль» (D81): после `./update.sh` на странице входа ссылка «Забыли пароль?» начнёт
присылать письмо со ссылкой на час. Ссылка в письме всегда ведёт на `https://KNITERP_DOMAIN` из `.env` — адрес из запроса
не используется. Без почты пароль меняет администратор организации: «Пользователи» → «Сменить пароль».

Проверить сейчас: `./monitor.sh status` — состояние всех проверок без оповещений. Пороги меняются переменными
`DISK_MIN_FREE_PCT`, `FULL_MAX_AGE_H`, `LOG_MAX_AGE_MIN`, `CERT_MIN_DAYS` в `.env`.

## 8. Обслуживание

| Задача | Команда |
|---|---|
| Состояние | `./monitor.sh status`, `docker compose ps` |
| Журнал приложения | `docker compose logs app --tail 200` |
| Перезапуск | `docker compose restart app` |
| Обновления Ubuntu | `apt-get update && apt-get upgrade` раз в месяц; затем `docker compose up -d` |
| Место на диске | `df -h /`, `du -sh /opt/kniterp/backups` |

Журналы контейнеров ограничены (5 файлов по 10 МБ), подробные SQL-запросы в журнал не пишутся.
