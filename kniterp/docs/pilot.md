# Пилот knitERP на фабрике

Цель пилота — склад фабрики четыре недели работает только в knitERP: остатки, поступления, перемещения, списания,
инвентаризация и закрытие месяца. Параллельный учёт в прежней программе или таблицах ведётся до приёмки (см. «Критерии приёмки»).

Принятые решения, на которые опирается пилот: D03 — в минус проводить нельзя; D05 — начальные остатки утверждает Владелец
или Руководитель, не автор документа; D15 — КПП организации 770501001.

## Участники

| Роль в пилоте | Роль в программе | Что делает |
|---|---|---|
| Владелец продукта | Владелец | принимает решения по открытым вопросам, утверждает остатки, закрывает период |
| Ответственный за пилот | Администратор | приглашает пользователей, следит за «Готовностью к запуску», собирает замечания |
| Старший кладовщик (по складу) | Старший кладовщик | вводит начальные остатки, проводит документы своего склада |
| Кладовщик | Кладовщик | готовит черновики документов и пересчёт инвентаризации |
| Начальник цеха | Руководитель подразделения | второй утверждающий начальных остатков, видит своих сотрудников |
| Бухгалтер (по желанию) | Бухгалтер | сверяет отчёты «Обороты» с бухгалтерией |
| Администратор сервера | — (доступа в программу не нужно) | сервер, резервные копии, выпуск версий — `docs/operations.md` |

## План и сроки

| Неделя | Что делаем | Кто | Результат |
|---|---|---|---|
| 0 (подготовка) | Сервер, мастер-ключ, миграции, `create-organization`, резервное копирование и проверка восстановления | администратор сервера | Владелец вошёл с 2FA; `/health` = Healthy; первая копия восстановлена на тестовом сервере |
| 0 | Сбор данных по шаблонам (ниже) | ответственный за пилот | заполненные файлы Excel |
| 1 | Реквизиты, структура, загрузка сотрудников, номенклатуры и контрагентов; склады; приглашение пользователей | Администратор | на «Готовности к запуску» зелёные все пункты, кроме остатков |
| 1 | Обучение по ролям — 1 час на группу по памяткам ниже, на тестовом стенде | ответственный за пилот | каждый провёл учебное поступление и списание |
| 1, последний день | Инвентаризация «на дату старта» и ввод начальных остатков по каждому складу; утверждение вторым человеком | старшие кладовщики, Владелец, начальник цеха | «Готовность к запуску» — все пункты зелёные; «Сверка» без расхождений; отпечаток «Проверки целостности» записан в акт |
| 2–4 | Ежедневная работа только в knitERP; замечания — через «Поддержку» на панели быстрого доступа | все | обращения разобраны в течение 1 рабочего дня |
| 4, конец месяца | Инвентаризация, «Сверка», «Проверка целостности», закрытие периода, сравнение с параллельным учётом | Владелец, старшие кладовщики | акт приёмки пилота |

Даты недель Владелец продукта назначает при старте; удобно начинать с первого числа месяца, чтобы закрытие периода совпало
с концом пилота.

## Сбор данных

Шаблоны скачиваются в программе (кнопка «Excel» → «Скачать шаблон» на странице раздела). Загрузка проходит целиком или не проходит
совсем: ошибки показываются по строкам, файл исправляется и загружается снова. Повторная загрузка того же файла ничего не дублирует.

| Данные | Где загружать | Ключ сопоставления | Источник на фабрике |
|---|---|---|---|
| Подразделения и должности | «Структура» (вручную) | наименование | штатное расписание |
| Сотрудники | «Сотрудники» → Excel | табельный номер | кадровый учёт; только ФИО, подразделение, должность, дата приёма |
| Номенклатура | «Номенклатура» → Excel | код | прежняя программа или складские карточки |
| Контрагенты | «Контрагенты» → Excel | ИНН и КПП, без ИНН — наименование | договоры с поставщиками |
| Склады | «Склады» (вручную) | — | — |
| Начальные остатки | «Начальные остатки» → строки из Excel | код позиции | инвентаризация на дату старта |

Персональные данные — только перечисленные поля. Паспортные данные, телефоны и адреса сотрудников в программу не вносятся (D31).

## Памятки по ролям

### Кладовщик
1. Вход: почта и пароль. Пароль — по ссылке приглашения (действует 72 часа).
2. «Складские документы» → «Новое поступление / перемещение / списание» → строки (вручную или из Excel) → «Сохранить».
   Провести черновик может Старший кладовщик.
3. Остаток в минус не уйдёт: в расходном документе видно, сколько есть на складе.
4. «Инвентаризация»: внесите факт или загрузите бланк пересчёта; отсутствующую позицию отметьте 0.
5. Вопрос или ошибка — «Поддержка» на панели справа вверху: раздел, где вы находитесь, подставится сам.

### Старший кладовщик
1. Всё, что делает кладовщик, плюс «Провести» и «Сторнировать» документы своего склада.
2. Ошибка в проведённом документе исправляется «Сторнировать» с причиной и новым документом — документы не удаляются.
3. Начальные остатки: документ по складу → строки из Excel → «Отправить на утверждение». Утверждает Владелец или
   начальник цеха — не вы.
4. Перед концом месяца: все черновики проведены или отменены, инвентаризация проведена.

### Руководитель подразделения (начальник цеха)
1. Видит своё подразделение и вложенные участки: сотрудников, структуру.
2. Утверждает начальные остатки, если их создал другой человек. Возврат на доработку — с причиной.

### Владелец
1. Вход с паролем и кодом из приложения-аутентификатора (2FA). Копия мастер-ключа — в сейфе.
2. «Готовность к запуску» — что ещё не сделано перед стартом.
3. Утверждение начальных остатков, просмотр всех отчётов и журналов.
4. Закрытие месяца: «Сверка» → «Проверка целостности» → записать отпечаток → «Закрытие периода».
   Открыть закрытый период назад можно только с причиной, она попадёт в журнал аудита.

### Администратор
1. Приглашения: «Пользователи» → почта, роль и область (склад или подразделение) → ссылку передать сотруднику лично.
2. Увольнение сотрудника блокирует его учётную запись сразу. Временно закрыть доступ — «Заблокировать».
3. Обращения в «Поддержку» — ответ в течение рабочего дня; повторяющиеся вопросы — в список доработок пилота.
4. «Журнал входов» раз в неделю: много неудачных попыток — повод проверить.

## Критерии приёмки пилота

1. Четыре недели все складские операции пилотных складов — только в knitERP.
2. Остатки по итогам инвентаризации конца месяца совпадают с учётными в программе, расхождения объяснены
   документами инвентаризации.
3. «Сверка» без расхождений и «Проверка целостности» без нарушений на дату закрытия периода; отпечаток записан.
4. Период пилотного месяца закрыт Владельцем.
5. Восстановление резервной копии проверено хотя бы один раз за пилот (`docs/operations.md`).
6. Ни одной ошибки «нет доступа» у пользователя, которому доступ нужен по роли (иначе — исправление прав до приёмки).
7. Обращения «Поддержки» закрыты или перенесены в план доработок с согласия Владельца продукта.

## Что остаётся открытым к пилоту

D01 (входят ли смены и выработка), D06 (аварийный доступ), D08 (вариант развёртывания и редакция SQL Server),
D17 (сроки хранения, RPO/RTO — пока действует допущение D54). Ответы не мешают старту склада; их стоит получить
до конца пилота.
