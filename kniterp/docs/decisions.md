# Журнал решений

Статусы: **открыт** — ждёт владельца продукта; **допущение** — разработка идёт по указанному варианту, его легко поменять, решением заказчика не считается; **принято** — подтверждено протоколом.

| ID | Вопрос | Статус | Как сейчас в коде |
|---|---|---|---|
| D01 | Граница первого запуска: входят ли смены, техкарты, выработка в P0 | открыт | Не реализуются. Сначала ядро доступа и структура — они нужны при любом ответе. |
| D02 | Склад раньше смен или наоборот | открыт | Порядок источника A (§14.41). Ядро доступа общее для обоих вариантов. |
| D03 | Отрицательный физический остаток | открыт | Проведение в минус запрещено (допущение D40). Право на проведение в минус в матрицу P0 не включено. |
| D04 | Владелец организации и директор — одна роль или разные | допущение | Роль «Владелец организации» по A §69.2. Директор не выделен отдельной ролью. |
| D05 | Кто утверждает начальные остатки | допущение | По A §69.3: создаёт Старший кладовщик, утверждает Владелец или Руководитель, не один человек. |
| D06 | Аварийный доступ | открыт | Не реализован. Сброс 2FA делает другой администратор; если единственный Владелец потерял телефон, нужен аварийный порядок. |
| D07 | Hangfire или BackgroundService | открыт | Фоновых задач пока нет. |
| D08 | Вариант развёртывания и редакция SQL Server | открыт | Код не зависит от ОС. В CI — SQL Server 2022 в Docker. |
| D09 | Микросервисы или монолит | допущение | Модульный монолит, ADR-0001. |
| D10–D14 | Техкарты, выпуск, нормы, сканирование | открыт | Не затронуто в первом срезе. |
| D15 | КПП 770501001 или 772301001 | открыт | КПП хранится с признаком «сверен». Несверенный КПП не выводится в печатные формы. |
| D16 | Пилот одной организации и несколько организаций на аккаунт | допущение | Модель поддерживает несколько организаций (ORG 01), пилот — на одной. |
| D17 | RPO/RTO, сроки хранения | открыт | Не затронуто. |
| D18 | Шкалы приоритетов P0–P3 двух источников | открыт | Используется шкала A §72. |
| D19 | Кто корректирует время и принимает работу | открыт | Не затронуто. |
| D20 | Логотип карточек | открыт | Не затронуто. |
| D21 | Тип дней (рабочие или календарные) и дата старта | открыт | День 1 не назначен. |
| D22 | Офлайн-факты после отзыва доступа | открыт | Не затронуто. |
| D23 | Новое. Правило «нельзя выдать право выше своего» (§69.7) и матрица §69.3 конфликтуют: у Владельца нет права создавать начальные остатки (разделение обязанностей), значит он не может назначить Старшего кладовщика | допущение | Владелец (право `access.admin.grant`) назначает любые роли; для остальных проверка действует полностью. |
| D24 | Новое. Блокировка учётной записи при нескольких организациях на аккаунт | допущение | Блокировка действует в пределах организации (`organization_members`), а не на весь аккаунт. |
| D25 | Новое. Сколько неудачных попыток входа до блокировки и на сколько | допущение | 5 неудачных попыток подряд (пароль или код 2FA) закрывают вход на 15 минут. Блокировка по учётной записи, а не по IP. |
| D26 | Новое. Требования к паролю | допущение | 10–128 символов, не совпадает с email, без обязательных цифр и знаков (NIST SP 800-63B). Удобна фраза из нескольких слов. |
| D27 | Новое. Срок сессии | допущение | 12 часов, продлевается при активности. Владелец и Администратор входят только с 2FA. |
| D28 | Новое. Как пользователь получает ссылку приглашения | допущение | Писем пока нет: администратор видит ссылку один раз и передаёт её сам. Ссылка действует 72 часа. |
| D29 | Новое. Область «своё подразделение» у Руководителя подразделения | допущение | Назначение роли с подразделением даёт доступ к нему и всем вложенным участкам. Роль «О» без подразделения не даёт ничего. |
| D30 | Новое. Что происходит с учётной записью при увольнении | допущение | Увольнение сотрудника блокирует доступ его учётной записи к организации в той же операции. Для этого нужно и право управления пользователями. |
| D31 | Новое. Состав карточки сотрудника в MVP | допущение | Табельный номер, ФИО, подразделение, должность, статус (работает / в отпуске / уволен), даты приёма и увольнения. Паспорт, телефон и иные персональные данные — отдельным срезом с правом `hr.personal_data.view`. |
| D32 | Новое. Справочники: типы номенклатуры, права на площадки и склады | допущение | Типы номенклатуры — фиксированный список: пряжа и сырьё, материалы, фурнитура, полуфабрикаты, готовая продукция, упаковка, прочее. Площадки и склады — с правами номенклатуры: просмотр `catalog.item.view`, изменение `catalog.item.edit`, архив `catalog.item.archive`. «О» у Старшего кладовщика на изменении — справочник общий для организации; область склада ограничит остатки и документы. |
| D33 | Новое. Код номенклатуры после архива | допущение | Код уникален в организации навсегда: архивный код не выдаётся новой позиции, чтобы старые документы не указывали на другую вещь. Позицию можно вернуть из архива. |
| D34 | Новое. Права на контрагентов и причины операций | допущение | В матрице P0 отдельных строк нет: используются права номенклатуры (просмотр — все, изменение — Владелец, Администратор, Старший кладовщик, архив — Владелец и Администратор). |
| D35 | Новое. Объём шаблонного импорта в первом срезе | допущение | Импорт и выгрузка — для номенклатуры: создание и обновление по коду, всё или ничего, до 5000 строк и 5 МБ, протокол ошибок по строкам и контрольные итоги. Контрагенты, сотрудники и начальные остатки — тем же механизмом в следующих срезах. |
| D36 | Новое. Стоимость в начальных остатках | допущение | Вводится только количество. Стоимость и себестоимость — после решения по учёту (фактическая себестоимость вне MVP 1.0). |
| D37 | Новое. Сколько раз вводится начальный остаток | допущение | Начальный остаток позиции на складе утверждается один раз; документов по складу может быть несколько (например, пряжа и фурнитура отдельно). Повтор позиции отклоняется при утверждении. Исправление — корректирующим документом в следующих срезах. |
| D38 | Новое. Область «подразделение» и складские права | допущение | Складские права ограничиваются складами из назначения. Руководитель подразделения с назначенным подразделением, но без склада, складских документов не утверждает — ему нужно назначение без области или со складом. Владелец утверждает по всем складам. |
| D39 | Новое. Кто проводит поступление, перемещение и списание | допущение | Проводит Старший кладовщик своего склада или Владелец (`warehouse.document.post`), в том числе собственный документ: принцип четырёх глаз — только для начальных остатков. Кладовщик заводит черновик; проводить ему можно отдельной выдачей права. Перемещение правит и проводит сторона склада-отправителя, кладовщик склада-получателя документ видит. |
| D40 | Новое (к D03). Проведение в минус | допущение | Запрещено: проведение и сторно не уводят остаток склада ниже нуля, проверка по текущему остатку (сумма всех движений) под блокировкой складов. Проверка «на дату документа» — вместе с закрытым периодом. |
| D41 | Новое. Дата сторно | допущение | Обратные движения пишутся датой документа: сторнированный документ не влияет на остатки ни на какую дату. После появления закрытого периода сторно в закрытом периоде потребует права `period.closed.reopen`. |

## Как закрыть вопрос
Владелец продукта отвечает в чате или в Issue на GitHub. Ответ вносится сюда со статусом «принято», датой и ссылкой; код меняется отдельным коммитом с тестом.
