# ADR-0001. Модульный монолит на .NET 10 и SQL Server

Статус: принято для первого контура (MVP 1.0). Основание: KA2617–KA2621, KA0844–KA0856, §3.7–3.9 ТЗ.

## Контекст
Разработчик один, отдельной команды DevOps нет. Основной язык — C#, СУБД — Microsoft SQL Server. Первая цель — надёжный внутренний контур фабрики. Паспорт продукта (KA0129) называет архитектуру «микросервисной, событийной» — это описание целевой платформы, а не первого контура (вопрос D09).

## Решение
- Одно приложение ASP.NET Core с Blazor Web App (interactive server).
- Слои: `Domain` (чистые правила, без зависимостей), `Application` (сценарии, транзакции, проверка прав), `Infrastructure` (EF Core 10, SQL Server), `Web`.
- Модули — папки и пространства имён внутри слоёв (`Organizations`, `Access`, `Audit`, далее `Structure`, `Catalog`, `Warehouse`). Модуль владеет своими таблицами; чужие данные читает через сервисы.
- EF Core для записи, Dapper/SQL — для тяжёлых отчётов (ADR-004 источника A), когда они появятся.
- Фоновые задачи — отложено до решения D07 (Hangfire или BackgroundService).
- Развёртывание — отложено до решения D08 (Windows Server + IIS или Ubuntu + Docker). Код не зависит от выбора.

## Последствия
- Микросервисная инфраструктура не создаётся, пока нет подтверждённой необходимости.
- Граница организации (tenant boundary) закладывается сразу: `OrganizationId` в каждой бизнес-таблице и в каждой проверке прав. Это требование ORG 01 источника Б и не мешает пилоту одной организации (D16).
